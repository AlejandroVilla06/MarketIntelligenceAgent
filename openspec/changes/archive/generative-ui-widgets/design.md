# Design: Generative UI Widgets

## Technical Approach

Inject `[WIDGET:type]{json}[/WIDGET]` markers into sub-orchestrator responses and parse them on the frontend to render visual React components inline with prose. The backend appends fully-constructed markers (valid JSON, built from MCP raw data) after the LLM prose analysis. The frontend `WidgetParser` tokenizes the streamed response, buffers incomplete markers until `[/WIDGET]` arrives, and delegates to `WidgetRenderer` which routes by type to domain-specific widget components. Zero new npm dependencies — pure SVG for sparklines, existing shadcn Card for layout, Tailwind `animate-pulse` for skeletons.

## Architecture Decisions

### AD1: Widget Marker Format

| Option | Tradeoff | Decision |
|--------|----------|----------|
| `[WIDGET:crypto]{json}[/WIDGET]` | Unique delimiter, unlikely in prose; requires escaping in code blocks | **Chosen** |
| `<widget-crypto data='...' />` HTML custom element | Fights with react-markdown parsing; ambiguous inside code blocks | Rejected |
| Separate SSE event type `{"type":"widget","data":...}` | Requires backend SSE restructuring; widgets lose inline position | Rejected |

**Rationale**: The `[WIDGET:type]` format is a 9-character ASCII prefix with zero false-positive risk in financial prose. Closing uses literal `[/WIDGET]` in output; `[\/WIDGET]` exists only in prompt instructions to prevent markdown renderers from interpreting the backslash.

### AD2: Streaming Buffer Architecture

| Concern | Mechanism |
|---------|-----------|
| Split markers across tokens | Accumulate tokens in `WidgetParser` buffer when `inWidget=true` |
| Infinite buffer (LLM never closes) | `MAX_WIDGET_TOKENS=2000` (~400 words) triggers flush as raw text |
| Slow stream (LLM stalls mid-widget) | `WIDGET_TIMEOUT_MS=5000` timer cancels skeleton, flushes buffer as text |
| Invalid JSON from LLM | `try/catch` on `JSON.parse()` → render as `<pre>` block, remove skeleton |

### AD3: Skeleton Strategy

Each widget type has a fixed-dimension skeleton using Tailwind `animate-pulse`. Skeletons are Card-shaped grey rectangles rendered immediately when `[WIDGET:` is detected. When the real widget arrives, the skeleton is replaced atomically — `key={widgetType}` on the wrapper ensures React remounts, preventing layout shift. Skeletons use the same Card wrapper as real widgets to guarantee identical dimensions.

### AD4: Widget Component Tree

```
ChatMessage.tsx
└── WidgetParser (processes text + widgets)
    ├── Plain text → react-markdown
    └── Widget markers → WidgetRenderer
        ├── "crypto"  → CryptoPriceCard
        ├── "macro"   → MacroIndicator  
        ├── "table"   → DataTable
        └── "calc"    → CalcResult
```

### AD5: Backend Marker Injection

The LLM is NOT instructed to write JSON markers (risk of invalid JSON). Instead, each sub-orchestrator's `answer()` method:
1. Fetches raw MCP data (already returns a dict internally)
2. Sends data to LLM for prose analysis (unchanged)
3. Constructs `[WIDGET:type]{json}[/WIDGET]` from the raw MCP data (code-generated valid JSON)
4. Appends the marker after the LLM prose

This ensures the JSON is always valid — generated by Python code, not the LLM.

## Data Flow

```
User: "Bitcoin price?"
  │
  ▼
RouterAgent → CryptoSubOrchestrator.answer()
  │
  ├── get_crypto_price("BTC") → raw CMC dict {symbol, price, change24h, marketCap, rank}
  │
  ├── _analyze_with_llm(query, raw_text) → prose: "Bitcoin cotiza a $81,372.18..."
  │
  ├── Construct widget marker:
  │   [WIDGET:crypto]{"symbol":"BTC","name":"Bitcoin","price":81372.18,
  │    "change24h":2.34,"marketCap":1.612e12,"rank":1}[/WIDGET]
  │
  └── Return: prose + "\n\n" + marker
  │
  ▼
orchestrator.ask_stream() → split by " " → yield word tokens
  │
  ▼
SSE stream: "Bitcoin cotiza a $81,372.18..." + marker tokens
  │
  ▼
Frontend chatStore.appendStreamToken()
  │
  ▼
WidgetParser (in ChatMessage.tsx)
  ├── Plain tokens → emit as text → react-markdown
  ├── Detects "[WIDGET:" → start skeleton + buffer
  │   ├── Timer: 5s
  │   ├── Max tokens: 2000
  │   └── On "[/WIDGET]" → JSON.parse → onWidget(type, data)
  └── WidgetRenderer routes to CryptoPriceCard
```

## Interfaces / Contracts

```typescript
// frontend/src/lib/types/widgets.ts

interface CryptoData {
  symbol: string
  name?: string
  price: number
  change24h: number
  change7d?: number
  marketCap?: number
  volume24h?: number
  rank?: number
}

interface MacroData {
  indicator: string
  value: number
  date: string
  previous?: number
  unit?: string
  source?: string
}

interface TableData {
  columns: string[]
  rows: (string | number)[][]
}

interface CalcData {
  formula: string
  inputs: Record<string, string | number>
  result: string | number
  interpretation?: string
}

interface SparklineData {
  data: number[]
  label?: string
  width?: number
  height?: number
  color?: string
}

type WidgetData = 
  | { type: "crypto"; data: CryptoData }
  | { type: "macro"; data: MacroData }
  | { type: "table"; data: TableData }
  | { type: "calc"; data: CalcData }
  | { type: "sparkline"; data: SparklineData }

interface WidgetSegment {
  type: "text" | "widget"
  content: string | WidgetData
}
```

## Testing Strategy

| Unit | `widgetParser` — valid marker extraction | Jest: feed `[WIDGET:crypto]{...}[/WIDGET]`, assert WidgetSegment output |
| Unit | `widgetParser` — invalid JSON fallback | Jest: feed malformed JSON, assert raw text output (no crash) |
| Unit | `widgetParser` — unclosed marker timeout | Jest + fake timers: verify buffer flushes after 5s |
| Unit | `widgetParser` — max tokens exceeded | Jest: feed 2001 tokens without close, assert flush |
| Unit | `widgetParser` — split marker across tokens | Jest: feed `[WIDGET:`, then `crypto]`, then content, then `[/WIDGET]` |
| Unit | `WidgetRenderer` — routes types correctly | Jest + React Testing Library: render with each type, verify correct component |
| Integration | Crypto widget renders from real marker | Mock SSE with marker, verify `CryptoPriceCard` shows price/change |
| Integration | Macro widget renders from real marker | Mock SSE with FRED marker, verify `MacroIndicator` shows value/date |
| Visual | Skeleton dimensions match widget | Storybook/Ladle: compare skeleton vs rendered widget dimensions |

## Migration / Rollout

No migration required. Feature is additive — widgets appear alongside existing prose. Rollback: remove widget parser from `ChatMessage.tsx` (revert to pure react-markdown) and remove marker append from sub-orchestrators. Widget components are isolated in `widgets/` directory with zero side effects. Backend markers render as plain text if frontend is rolled back.
